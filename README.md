> [!WARNING]
> Pre-alpha and under active development. Nothing here is stable; terminology, structure, and behavior can all still change without notice.

You scaffold a self-contained **Workspace** per **Target**, and exhaust gives an agent what it needs to probe that Target autonomously and exhaustively: a **Rig** of pinned tools, a **Playbook** of verticals to work through, and a **Harness** that drives the loop. To exhaust a Target is to work through every known angle until the options are spent, not to stop at the first finding.

## Quick start

With Nix (recommended — provisions the Rig's pinned tools, `nmap` and `curl` included, and `just`, reproducibly):

```bash
git clone https://github.com/kzndotsh/exhaust.git
cd exhaust
nix develop
uv sync --group dev && uv run lefthook install
```

Without Nix: `uv sync --group dev` still gives you a working `exhaust` CLI, but any Rig tool a run actually calls (`nmap`, `curl`) has to already be on your `PATH` yourself.

```bash
git clone https://github.com/kzndotsh/exhaust.git
cd exhaust
uv sync --group dev
```

```bash
# Scaffold a Workspace for a Target
uv run exhaust new roundcube

# The generated vertical catalog (empty until the Playbook locks and skill files exist)
uv run exhaust catalog generate
uv run exhaust catalog check
```

`exhaust new <target>` writes `AGENTS.md`, `BRIEF.md`, a `sandbox/` placeholder, and `poc/`/`findings/` directories. It never writes a `SCOPE_CONTRACT.yaml`: with none present, anything built on top of this is confined to the Sandbox by default (see [ADR 0003](docs/adr/0003-scope-contract-gates-real-targets.md)).

## How it's shaped

- **Scope Contract gates real Targets, by target and by extent.** No contract in a Workspace means Sandbox-only, and the gate fails closed on anything missing or malformed — never permissive by default. A contract's `extent` is `recon` or `full` ([ADR 0024](docs/adr/0024-extent-is-a-closed-two-tier-vocabulary.md)), checked against what each Rig method declares it needs, not just the target string. [`src/exhaust/scope_contract.py`](src/exhaust/scope_contract.py)
- **Findings are append-only.** A Finding is never deleted; Verdicts (confirmed, false-positive, duplicate, fixed, accepted-risk, needs-confirmation) are recorded on it over time, and a human's `accepted_risk` verdict can't be silently overwritten by automation. [`src/exhaust/findings.py`](src/exhaust/findings.py)
- **A `confirmed` Verdict needs a host-run Oracle**, not just the agent's self-report — the one gap found, in some form, in nearly every comparable tool audited so far ([ADR 0008](docs/adr/0008-confirmed-requires-a-host-run-oracle.md)). [`src/exhaust/oracle.py`](src/exhaust/oracle.py) defines the mechanism shapes `findings.py` requires before accepting one; no actual host-run check is wired up yet.
- **Untrusted Target output is delimited, never treated as instruction.** A random, nonce-tagged boundary marks anything that came back from the Target as data for the agent to read, not a command to follow — a hostile Target can't predict and forge it in advance ([ADR 0009](docs/adr/0009-untrusted-target-output-is-delimited.md)). [`src/exhaust/delimiter.py`](src/exhaust/delimiter.py)
- **Evidence promotion is parent-trusted, never agent-written.** An investigating agent only writes to its own scratch space; copying a file into a Finding's permanent evidence is a separate, trusted step that rejects symlinks and path traversal and re-checks the copy afterward ([ADR 0010](docs/adr/0010-evidence-promotion-is-parent-trusted.md)). [`src/exhaust/evidence.py`](src/exhaust/evidence.py)
- **No hand-maintained catalog.** Whatever lists the Playbook's verticals is generated by reading skill files directly ([ADR 0016](docs/adr/0016-no-hand-maintained-vertical-catalog.md)), checked in CI so it can never silently drift.
- **A per-vertical ledger, not a heuristic, decides when a Workspace is done.** Every vertical carries an explicit state, and leaving `blocked` is never silent ([ADR 0005](docs/adr/0005-harness-done-is-a-per-vertical-ledger.md), [ADR 0015](docs/adr/0015-crash-mid-real-target-action-blocks-not-retries.md)). [`src/exhaust/ledger.py`](src/exhaust/ledger.py)
- **The Rig wraps pinned external tools behind one call gate.** A method not on a tool's own closed list is refused before the tool ever runs ([ADR 0012](docs/adr/0012-rig-wraps-a-pinned-tool-catalog.md), [ADR 0018](docs/adr/0018-tool-bridges-expose-a-narrow-enumerated-surface.md)). `nmap` is the first tool pinned, wrapped as two recon-tier, non-mutating methods ([ADR 0026](docs/adr/0026-nmap-is-the-rigs-first-pinned-tool.md)); `curl` is the second, wrapped as three consequential, full-extent payload-submission methods (`get`, `post_form`, `post_multipart`) covering every input shape the `injection` vertical enumerates — query parameters, form fields, headers and cookies, path segments, and uploaded filenames ([ADR 0027](docs/adr/0027-curl-is-the-rigs-second-pinned-tool.md)). Both are provisioned reproducibly by [`flake.nix`](flake.nix), pinned to the exact nixpkgs commit that carries them. `exhaust doctor` checks whatever's actually on `PATH` against the pin, since Nix is a recommendation, not an enforcement; `exhaust run` prints the same check as a non-fatal warning before a run starts. [`src/exhaust/rig/`](src/exhaust/rig/)
- **The Harness is the one chokepoint between an agent's proposed actions and the privileged domain calls they trigger** ([ADR 0001](docs/adr/0001-agent-first-design.md), [ADR 0007](docs/adr/0007-verdicts-are-recorded-through-typed-tools.md)). Every `AgentAction` variant is wired up end to end: `SandboxCall` and `RealTargetCall` dispatch through the Rig, re-checking the Scope Contract for the latter; `SelfReport`'s exhaustion claims are checked against the Findings store and the attempt log, not taken on trust. [`src/exhaust/harness/`](src/exhaust/harness/)
- **A consequential real-Target action or an exhaustion claim waits for a human, not just a scope check** ([ADR 0023](docs/adr/0023-consequential-real-target-actions-wait-for-a-human.md)). A Rig bridge marks its own methods consequential; a matching call is held as a pending approval, independent of the ledger's `blocked` state, until a human resolves it — and approving doesn't execute it, the agent has to propose it again. [`src/exhaust/approvals.py`](src/exhaust/approvals.py)
- **`AgentSession`'s first implementation is backed by Pi, gated by a thin extension that relays every decision to the Harness** ([ADR 0025](docs/adr/0025-agentsession-is-backed-by-pi-gated-by-a-thin-relay-extension.md)). Pi's model loop runs as a subprocess; the one piece of TypeScript this introduces forwards a proposed tool call to the Harness over a Unix socket and decides nothing itself — every actual dispatch, scope check, and approval still happens in the same Python code every other backend would use. Verified end to end against a live model: a real `pi` subprocess, the real gate extension, and a live Claude call all completed the handshake and one full relay round trip. Wired into `exhaust run` ([`cli/run.py`](src/exhaust/cli/run.py)), which can now dispatch a `SandboxCall`/`RealTargetCall` naming `nmap` or `curl`, the Rig's two pinned tools, not just `SetVerticalState`/`SelfReport` turns. [`src/exhaust/harness/pi_adapter/`](src/exhaust/harness/pi_adapter/)
- **The agent never holds the real LLM provider credential.** A local, stdlib-only proxy holds the real key, hands the agent a separate budget-capped virtual key, checks the run's remaining budget before forwarding a call, and prices real token usage from the response once it returns ([ADR 0021](docs/adr/0021-agent-never-holds-the-real-llm-credential.md)). `exhaust run --anthropic-key-file` wires it in; for Pi specifically, the virtual key reaches the subprocess as a file Pi itself reads, never an environment variable. Verified against a real model call through a live Anthropic-compatible endpoint. [`src/exhaust/harness/credential_proxy.py`](src/exhaust/harness/credential_proxy.py)

## Project layout

```
src/exhaust/
├── cli/                 # Typer commands: new, catalog generate/check, run, doctor
├── workspace.py         # Scaffolds a Workspace (ADR 0001, 0006)
├── scope_contract.py    # The Scope Contract gate (ADR 0003)
├── catalog.py           # Vertical catalog generator (ADR 0016)
├── findings.py          # Append-only Finding/Verdict store (ADR 0004, 0007, 0019)
├── oracle.py            # Oracle mechanism shapes (ADR 0008)
├── ledger.py            # Per-vertical state machine (ADR 0005, 0015)
├── delimiter.py         # Wraps untrusted Target output (ADR 0009)
├── evidence.py          # Parent-trusted evidence promotion (ADR 0010)
├── attempts.py          # Per-vertical tool-attempt log, backs SelfReport checks (ADR 0005)
├── approvals.py         # Pending human approvals for consequential actions (ADR 0023)
├── rig/                 # Pinned external tool catalog + the one call gate (ADR 0012, 0018, 0026)
│   └── wrappers/        # One ToolBridge per tool; default_bridges() is the registry
└── harness/             # Orchestrator; composes every domain module (ADR 0001, 0005, 0007)
    ├── credential_proxy.py  # Local budget-capped proxy; agent never holds the real key (ADR 0021)
    └── pi_adapter/      # AgentSession backed by Pi; the one TypeScript file lives here (ADR 0025)
```

Lint, format, strict types, numpy docstrings, import boundaries, and tests all run the same way locally and in CI — see the [justfile](justfile) (`just check`) and [lefthook.yml](lefthook.yml). The one exception is `harness/pi_adapter/gate/extension.ts`, the single TypeScript file in the tree: it's checked with `tsc --noEmit` against the real `@earendil-works/pi-coding-agent` types by hand, not wired into `just check` or CI yet.

## Design docs

The design is ahead of the code. Start here if you want the reasoning, not just the result:

- **[GLOSSARY.md](GLOSSARY.md)** — the vocabulary: Target, Workspace, Sandbox, Rig, Scope Contract, Brief, Finding, Verdict, Oracle, Playbook, Vertical, Harness, Disclosure.
- **[docs/adr/](docs/adr/)** — 27 architecture decision records, each a specific, evidenced call: how findings are verified, how the Playbook is shaped, the safety boundaries around testing a real Target, when a consequential action waits for a human, what extent of testing a Scope Contract actually authorizes, what backs the agent's own conversation loop, which tool the Rig pins first.
- **[docs/research/](docs/research/)** — 25 audits of comparable tools (security-research harnesses, pentest platforms, skill libraries), plus dedicated audits of the agent-backend landscape, harness-engineering principles, LiteLLM, the Pi coding-agent toolkit, and the open Agent Skills ecosystem, each stating plainly what exhaust adopted, rejected, and why. Most of the ADRs are built on these.
- **[docs/artifacts/](docs/artifacts/)** — working design material that isn't a settled ADR or a finished tool audit: the still-open Playbook vertical-catalog proposal, the skills-system spec (directory shape, front-matter schema, authoring rules, template, and linting for vertical skill files), and the architect-synthesized `PiAgentSession` design sketch (with its own reconciliation log of what changed once a code-review pass and a real-package verification spike checked it against reality).

## Responsible use

Exhaust is built around a responsible-disclosure discipline from the ground up — see the Scope Contract and Disclosure concepts in [GLOSSARY.md](GLOSSARY.md). It is meant for testing systems you own or are explicitly authorized to test.
