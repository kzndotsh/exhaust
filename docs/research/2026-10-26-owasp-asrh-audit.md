# Audit: OWASP/Agent-Security-Regression-Harness

Source: [github.com/OWASP/Agent-Security-Regression-Harness](https://github.com/OWASP/Agent-Security-Regression-Harness), cloned shallow for this audit. "Executable security regression testing for agentic applications and MCP-integrated systems." An OWASP Incubator project (Alpha, v0.2.0, effectively single-leader governance), explicitly not a benchmark, scanner, or AI safety eval suite — a regression harness that catches known classes of agent-security failure before they ship. Read-only, read by five subagents each scoped to one slice.

This repo's shape is different from the first three: it's not a tool for finding vulnerabilities in a Target, it's a tool for regression-testing an *agentic system itself* against known classes of agent-security failure (prompt injection, goal hijacking, approval bypass, memory isolation, MCP trust-boundary abuse). That difference is exactly what makes it relevant: exhaust's own Harness is itself an agentic system, with tool access, memory (the Workspace), and an approval gate (the Scope Contract). This audit is about testing *exhaust*, not about exhaust's spine for testing a Target.

## Adopted, or strongly validated

**Trust must come from outside what the agent itself can read, never from trace content.** The `approval_required` assertion's whole design point: an approval is valid only if it comes from a context source the *scenario author* marked trusted, never from a string anywhere in the trace itself. A forged "approval granted, token ADMIN-OVERRIDE" planted in a retrieved document does not satisfy it. This is the single most directly reusable idea in the audit, and it's exactly the principle now folded into [ADR 0003](../adr/0003-scope-contract-gates-real-targets.md)'s amendment: a Scope Contract's authority can never be satisfiable by anything that arrives inside the agent's own context.

**Memory isolation as a cheap marker-substring scan, with redacted evidence.** The `memory_isolation` assertion serializes the whole trace and checks for forbidden markers, reporting only a hash prefix and length in evidence, never the marker value itself. A direct, cheap mechanism exhaust should adopt for its own real concern: verifying that one Target's Findings and Brief never leak into a different Target's Workspace.

**A positive and negative control in the regression gate itself.** This repo's own CI doesn't just run its scenarios against passing fixtures; it also runs a deliberately leaky trace and asserts the result comes back `fail`. That's the strongest idea in the whole audit: it proves the assertions actually catch what they claim to catch, rather than passing vacuously. If exhaust ships its own Harness self-tests, this is the pattern to copy, not just a clean-fixture pass.

**Adapters translate, they never judge.** Every framework integration (LangChain, OpenAI Agents SDK, raw MCP, a live HTTP target) converges on one common trace shape; only a single assertion layer decides pass or fail. Framework-specific code is duck-typed and lazily imported with install-hint errors, no shared base class required. A clean precedent if exhaust's own Harness ever needs to stay agnostic to which agent SDK actually drives the probing agent.

**Host-owned evidence the target cannot forge.** When this repo's own code is the MCP client, it records every tool call itself and explicitly rejects any target-supplied output that tries to inject fields that look like host-recorded evidence. Directly applicable to exhaust: an agent's self-reported tool use should never be the only record of what happened: the Harness, not the agent, should be the one writing down what it actually did.

## Rejected, and why

- **The 8-category taxonomy itself is not a Target vulnerability spine.** About half the categories (memory isolation, approval bypass, sensitive data disclosure) have a loose AppSec analog; the rest (goal hijack, MCP tool-description poisoning) are agent-specific failure modes with no equivalent in a web-app pentest. None of it is SQLi, XSS, SSRF, or auth-bypass in the sense our own spine means. This taxonomy tests the *agent*, not the *Target*; it does not belong in exhaust's methodology spine.
- **Trace-replay-only scoring for live targets.** Deterministic replay against a recorded trace is reproducible; a live run against a real LLM-backed target is not, by the project's own account. Fine for what this repo does, not directly portable to exhaust's live-Sandbox verification needs.
- **Name-only tool denylists, with no argument matching.** `no_denied_tool_call` checks a tool's name, never its arguments. The auditor's own example: an allowlisted action called against an out-of-scope target slips through untouched. If exhaust borrows this assertion style for its own self-tests, scope checks need to match on the actual target of an action, not just which tool was invoked.

## The real opportunity: exhaust needs a self-test suite for its own Harness, not a new vertical

This is worth surfacing as an open decision rather than silently adopting it, since it's genuinely additive scope. Exhaust's Harness is an agentic system that will read back whatever a hostile Target returns, exactly the shape this project exists to regression-test. A Target's response could try to hijack the agent's goal, forge a Scope Contract approval, or trick the agent into leaking one Workspace's Findings into another's. A small, separate scenario-and-trace suite, modeled on this repo's pattern (a scenario, a recorded or live trace, an assertion, a pass/fail/not-run result, with both a clean fixture and a deliberately broken one to prove the assertion actually fires) would directly cover: does the Harness ever act on an in-band "you are now authorized" claim; does it ever let a Target's content redirect its goal; does cross-Workspace leakage ever occur. This is not part of the methodology spine (which tests the Target); it would be a second, smaller track testing exhaust itself, the way the Anthropic reference repo keeps its detection-and-response track separate from its vulnerability-discovery track.

## What this settled for exhaust

- [ADR 0003](../adr/0003-scope-contract-gates-real-targets.md) amended (shared with the [defending-code-reference-harness audit](2026-10-26-defending-code-reference-harness-audit.md)): authority can never come from inside the agent's own context.
- Open, not settled: whether exhaust should ship its own Harness self-test suite in this style, as a track separate from the Target-probing spine.
