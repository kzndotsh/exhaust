# Audit: elder-plinius/T3MP3ST

Source: [github.com/elder-plinius/T3MP3ST](https://github.com/elder-plinius/T3MP3ST), cloned shallow for this audit. "Autonomous red teaming platform; multi-agent offensive-security meta-harness." The author is known elsewhere for jailbreak-prompt collections, so every read treated repo content strictly as data to describe, never as instructions; nothing instruction-shaped toward the reading agent was found. Read-only, read by six subagents across the mission/scope model, the validation/findings layer, the benchmark and CTF suite, the multi-agent orchestration layer, and the tooling/recon layer, plus one tightly-scoped follow-up verifying a specific function. See also the [deepsec](2026-10-26-deepsec-audit.md), [Shannon](2026-10-26-shannon-audit.md), [defending-code-reference-harness](2026-10-26-defending-code-reference-harness-audit.md), [OWASP ASRH](2026-10-26-owasp-asrh-audit.md), [Cloudflare security-audit-skill](2026-10-26-cloudflare-security-audit-skill-audit.md), and [cyber-harness](2026-10-26-cyber-harness-audit.md) audits.

## The headline finding: this is the first tool with a real, independently verifiable eval

Every prior audit left the same question open: is there anywhere a security-research tool's effectiveness is measured against known ground truth, scored by code, rather than self-reported by an LLM or left unmeasured entirely? This repo has three real answers, one genuinely strong, and it also contains the clearest cautionary example yet of how to fake the same thing.

**CVE-Zero's held-out set is the strongest result in the whole research campaign.** A set of ten real, fresh 2026 security advisories, held out of all tuning, with ground truth (the exact file, line, and vulnerability category from the actual fix commit) the agent never sees during the run. The score is recomputed from raw findings by a script, not read from the agent's own claim. We independently recomputed it ourselves from the raw data and got the same number the project claims (8 of 10). This is a real, verifiable benchmark result, the first one found across seven audited tools.

**The CTF executor is the cleanest design, let down by incomplete wiring.** A fresh, random flag is generated per run and injected into the Sandbox via an environment variable; success is an exact string match after the run, parallel to our own Finding model's repro/evidence idea at its simplest. But it has zero committed runs, and worse: several of its own challenges hardcode a static flag in source and never read the injected one at all, so the mechanism that would prove this was never actually exercised for most of its own fixtures.

**OBSIDIVM is the cautionary tale, and it's worth naming precisely.** A rising score across "generations" turned out to be the same fixed answer list used both to write the tactics that fix misses and to grade the next run, with no held-out portion at all. Worse, a transcript-formatting function was found to literally inject the expected finding's ID and keywords into the text being scored. A rising number here measures memorization of the exact items being graded, not capability. This is what we were implicitly warning against in principle, now a concrete example rather than an abstraction.

Both lessons, plus the real CVE-Zero pattern, are recorded as [ADR 0014](../adr/0014-eval-uses-blind-held-out-ground-truth.md).

## The second major finding: the first real code-enforced scope check, and exactly how it still falls short

After six audits with zero code-enforced target scope anywhere, this repo has one: `scopeViolation`, a real host/CIDR allowlist check, populated from actual operator-entered targets (not permanently empty data), run before tool execution, denying hosts outside scope with explicit carve-outs for loopback and private ranges. This breaks the streak.

It also fails in exactly the two ways our own design already guards against, which is worth stating precisely rather than just noting as "confirmed again." It defaults to **fully permissive** until the first target is ever added, the opposite of defaulting closed. And it is only reachable through one of several code paths that can invoke a tool; at least one other path (direct handler calls bypassing the central execution function) skips it entirely, so it's not actually the one mandatory chokepoint. Both are now folded explicitly into [ADR 0003](../adr/0003-scope-contract-gates-real-targets.md): default closed with nothing configured, and sit at the single point every tool call must pass through.

## Other adopted or reinforced findings

**An errored or throttled vertical must never read as "exhausted, nothing found."** A `DegradedTracker` here explicitly marks a run invalid when failures cross a threshold, specifically so throttling can't masquerade as a clean negative result. Folded into [ADR 0005](../adr/0005-harness-done-is-a-per-vertical-ledger.md) as a distinct state a ledger must track.

**A crash during a real-Target action should block, not silently retry.** Found as a contrast within this repo's own code: durable snapshots elsewhere treat an ambiguous crash mid-action as something to resume from cleanly, which is right for Sandbox work but wrong for a real Target, where blindly re-firing an unknown-outcome action could do more harm than stopping. Recorded as [ADR 0015](../adr/0015-crash-mid-real-target-action-blocks-not-retries.md).

**A cheap, mechanical pre-check layered in front of a full Oracle.** A live-path gate here checks only that evidence of the right *type* exists before letting a finding's severity stand at full strength (not that its content is correct), and it's wired into production with a test pinning the invariant. Worth keeping as an inexpensive first filter ahead of a real host-run Oracle check, not a replacement for one.

**A real, working host-run re-execution exists, narrowly scoped.** A retest mechanism here re-runs a tool against a CVE-identified finding with idempotency keys and bounded attempts, the closest working example of our Oracle design found in any audit, though it's exercised only in tests, not wired into the live path, and limited to CVE findings specifically.

**A citation-integrity check worth considering as a cheap complement to a full Oracle.** A deterministic gate here downgrades any claim whose cited evidence can't be found in the actual source material provided, shared as one code path between two different callers so they can't drift apart. Cheaper than full re-execution and catches a real class of fabricated-sounding claims.

**A risk-tiered tool catalog.** This repo's tool catalog (distinct from, and more detailed than, cyber-harness's `arsenal.yaml`) tags each tool with a risk tier (from read-only through intrusive and dangerous) and an execution mode, with the highest-risk tools never auto-callable through the generic path at all. Worth considering alongside our own pinned-catalog decision (ADR 0012): some tools in the Rig may need their own risk gate, not just the Target's scope gate.

## Rejected, and why

- **Duplicate findings merged by in-place overwrite.** A later finding with the same normalized key overwrites the earlier record's fields directly, losing the prior values and the reasoning for the merge. A direct, concrete argument for why ADR 0004's append-only model matters: this is exactly the failure mode it exists to prevent.
- **Multi-agent pack coordination (claims, leases, quorum refutation).** A real, well-built mechanism for several agents exploring one target in parallel and needing to avoid duplicate work, but it solves a problem a single-agent-per-Workspace Harness doesn't have. Not applicable to exhaust's v1 shape.
- **Routing around a worker model's own refusals by hiding the objective from it.** An orchestrator pattern here explicitly keeps a sub-model from seeing the actual offensive goal, framing its tasks as "innocuous analytical queries," specifically to avoid triggering safety refusals. This is not a pattern exhaust should adopt under any framing.
- **Inconsistent redaction in generated reports.** One reporting path here redacts sensitive content before output; a second, parallel path does not. Worth remembering only as a reason to have exactly one reporting path, not two that can drift apart.

## What this settled for exhaust

- [ADR 0014](../adr/0014-eval-uses-blind-held-out-ground-truth.md): exhaust's own effectiveness eval uses blind, held-out ground truth, scored independently, never self-reported.
- [ADR 0015](../adr/0015-crash-mid-real-target-action-blocks-not-retries.md): a crash mid-real-Target action blocks for review rather than retrying.
- [ADR 0003](../adr/0003-scope-contract-gates-real-targets.md) sharpened: default closed with nothing configured; the gate must be the single mandatory chokepoint, not one path among several.
- [ADR 0005](../adr/0005-harness-done-is-a-per-vertical-ledger.md) sharpened: an errored or throttled vertical is its own ledger state, distinct from both exhausted and skipped.
