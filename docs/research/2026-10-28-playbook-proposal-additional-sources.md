# Additional sources against the 2026-10-26 Playbook proposal: OWASP Top 10:2025, Bugcrowd VRT, CWE Top 25

A follow-up to [`2026-10-26-playbook-proposal-cross-check.md`](2026-10-26-playbook-proposal-cross-check.md), which checked the draft against WSTG, ASVS, and PortSwigger's Web Security Academy — three testing-*methodology* taxonomies. None of those is OWASP's own Top 10 risk ranking, and it turns out that ranking was updated for 2025, after the original cross-check and unseen by it. This document checks three more primary sources: the current OWASP Top 10:2025, Bugcrowd's Vulnerability Rating Taxonomy (an industry bug-bounty triage standard), and the 2024 CWE Top 25. Same framing as the first cross-check: this adds findings, it settles nothing, and the Playbook catalog stays unlocked regardless.

Primary sources actually fetched (live):

- OWASP Top 10:2025 index and three individual category pages (A01, A03, A10): <https://top10.owasp.org/2025/>
- Bugcrowd Vulnerability Rating Taxonomy 1.10, top-level categories: <https://bugcrowd.com/vulnerability-rating-taxonomy/1.10.json>
- CWE Top 25 (2024), MITRE's archived list: <https://cwe.mitre.org/top25/archive/2024/2024_top25_list.html>
- CAPEC-1000 (Mechanisms of Attack) was checked but not usably fetched (page exceeded fetch size limits); not represented below beyond noting it exists as an attack-*mechanism* taxonomy, not a vulnerability-*category* one, so it doesn't map cleanly onto vertical-style weakness categories the way the others do.

## What OWASP Top 10:2025 actually says

Confirmed directly from `top10.owasp.org/2025/`, not a secondary roundup: **A01 Broken Access Control, A02 Security Misconfiguration, A03 Software Supply Chain Failures, A04 Cryptographic Failures, A05 Injection, A06 Insecure Design, A07 Authentication Failures, A08 Software or Data Integrity Failures, A09 Security Logging and Alerting Failures, A10 Mishandling of Exceptional Conditions.**

Three findings against the current proposal:

1. **Security Misconfiguration is now #2**, up from #5 in 2021. This independently reinforces the config/deployment-management gap the first cross-check already flagged — it's not a marginal category in the current standard, it's the second-ranked one.
2. **Software Supply Chain Failures is a new #3**, broader than 2021's "Using Components with Known Vulnerabilities." Fetched its own page directly: it covers the whole build/distribute/update pipeline (untracked transitive dependencies, weak CI/CD, missing change management), not just known-CVE components. OWASP's own page says it's explicitly **hard to test for directly** — detection relies on SBOM generation and dependency-scanning tools (Dependency-Track, NVD/OSV lookups), not live black-box probing. That's a different *kind* of testing than exhaust's recon-and-exploit model handles today. This doesn't argue for promoting the existing `supply chain` reserved vertical to required — if anything it confirms gated is right, since its real detection path needs a different mechanism (source/SBOM access) than a confirmable live-Target signal.
3. **A10 Mishandling of Exceptional Conditions is brand new for 2025** — improper error handling, logic/control-flow bugs, "failing open," missing checks after an exception. Fetched its own page: 24 CWEs, themes include information leakage through errors (already `information disclosure`'s territory), insufficient privilege checks after an error (already `access control`'s), and logic/control-flow errors (already `business logic`'s). This isn't a gap in coverage so much as a gap in *explicit instruction* — nothing in the current required set tells an agent to specifically probe error paths and exception handling as part of those three verticals' own procedures. Confirmed A01's own page: SSRF is CWE-mapped into Broken Access Control but not described as folded into its scope — the proposal's separate required `SSRF` vertical isn't contradicted by this.

**Not applicable to exhaust's model, confirmed by reading their actual scope**: A06 Insecure Design is a secure-development-process category (threat modeling, secure design patterns), not an externally-confirmable trust boundary — nothing to gate or require. A09 Security Logging and Alerting Failures needs visibility into the Target's own logs/monitoring, which a black-box external agent generally doesn't have. Both are real OWASP categories with no clean translation into exhaust's vertical shape; noting their absence here so it's a recorded decision, not a silent gap.

## What Bugcrowd's VRT adds

Bugcrowd's taxonomy is built for rating *already-found* vulnerabilities for bug-bounty payout, not for deciding what to test — a different job than exhaust's Playbook. Still, its 23 top-level categories are a real, heavily-used industry standard, fetched directly from the JSON: Server Security Misconfiguration, Server-Side Injection, Broken Authentication and Session Management, Sensitive Data Exposure, XSS, Broken Access Control, CSRF, **Application-Level Denial-of-Service**, **Unvalidated Redirects and Forwards**, External Behavior, Insufficient Security Configurability, Using Components with Known Vulnerabilities, Insecure Data Storage, Lack of Binary Hardening, Insecure Data Transport, Insecure OS/Firmware, Broken Cryptography, Privacy Concerns, Network Security Misconfiguration, Mobile Security Misconfiguration, Client-Side Injection, Automotive Security Misconfiguration, Indicators of Compromise.

Two findings:

1. **Application-Level DoS is a first-class, actively-rated industry category**, not a fringe concern. This matters directly against the first cross-check's finding that no primary source models DoS as confirmable — Bugcrowd confirms the industry still recognizes and pays for it as a distinct class, even though (per the first cross-check) WSTG dropped it from testing *methodology* specifically over the safety of actively triggering it. Those aren't the same claim: "is this a real, recognized vulnerability class" (yes, per Bugcrowd) and "can exhaust safely gate testing for it with a confirmable recon signal" (still genuinely unresolved, per WSTG/ASVS/PortSwigger all declining to model a trigger). This softens, but doesn't settle, the first cross-check's recommendation to drop it.
2. **Unvalidated Redirects and Forwards (open redirect) is missing from the proposal entirely** — not required, not reserved, not declined. It's cheap to check, broadly applicable (login/logout flows, OAuth redirects), and a real standing category in Bugcrowd's taxonomy (WSTG also covers it under input-validation testing, though not as its own top-level 4.x category — it's one level down). A genuine, previously-unflagged gap.

Mobile/automotive/OS-firmware/binary-hardening categories are out of scope for the same reason the Cloudflare companions were declined in the original proposal — past exhaust's actual web-app target history.

## What the CWE Top 25 (2024) adds

Fetched the full ranked list directly from MITRE's archive. It's a frequency×severity ranking of real CVEs, not a testing taxonomy, so it mostly confirms rather than reveals: XSS (#1), SQLi (#3), CSRF (#4), path traversal (#5), OS command injection (#7), missing authorization (#9), unrestricted file upload (#10), improper authentication (#14), improper privilege management (#15), **deserialization of untrusted data (#16)**, information exposure (#17), SSRF (#19), hard-coded credentials (#22), uncontrolled resource consumption (#24, i.e. DoS), missing authentication (#25) — every one of these already maps onto an existing required or reserved vertical in the proposal. The one data point worth naming: deserialization ranks #16 by real-world CVE frequency×severity, ahead of SSRF (#19) and well ahead of several required-list items — a real-world-impact argument that cuts *against* my earlier recommendation to demote it from required to gated purely on PortSwigger's "Advanced" grouping. Worth weighing both signals together, not just one.

## Net effect on the standing recommendations

- Config/deployment-management and crypto/TLS as required: reinforced further, not just by WSTG/ASVS this time but by OWASP's own current #2 and #4 ranked risks.
- Deserialization required-vs-gated: genuinely closer to a toss-up than it looked after only the first cross-check. PortSwigger's own grouping argues gated; CWE's real-world frequency×severity ranking (#16, ahead of SSRF) argues it still earns a required slot. Flagging as unresolved rather than picking a side this time.
- DoS/ReDoS: don't drop it outright. Keep it reserved, but the open problem is specifically writing a confirmable gate signal — Bugcrowd confirms the category is real and rated industry-wide; nobody checked here (WSTG, ASVS, PortSwigger, Bugcrowd, CWE) actually describes a safe, confirmable pre-test trigger for it.
- New, clean finding: **Unvalidated Redirects and Forwards (open redirect)** has no record anywhere in the proposal — not required, reserved, or declined. Worth an explicit decision, even if that decision is "fold into access control's or client-side's own procedure, no new vertical."
- New, clean finding: **A10:2025 Mishandling of Exceptional Conditions** has no explicit instruction anywhere, though its substance already falls inside `information disclosure`, `access control`, and `business logic`'s existing scope — likely a procedure-writing note for those three verticals, not a new vertical.
- Two OWASP 2025 categories (A06 Insecure Design, A09 Security Logging and Alerting Failures) checked and found genuinely inapplicable to exhaust's external black-box model — recorded as a considered-and-declined decision, not a silent absence.
