# The agent never holds the real LLM provider credential

Whatever process actually runs the agent's model calls does not hold the real Anthropic (or other provider) API key directly. A local proxy sits between the agent and the provider, holding the real credential itself, and issues the agent a separate, budget-capped key scoped to that one Workspace's run.

An AIxCC-descended orchestration framework for autonomous bug-finding systems does exactly this: every CRS instance it runs, including ones that wrap Claude Code or Codex directly, talks to a local LiteLLM proxy rather than the provider directly, so the real key never enters the agent's own container, and a dollar budget is enforced at that proxy, not merely tracked and read back after the fact. The same project hands the agent's own credential to its container as a file, not an environment variable, specifically because a file with restricted permissions is harder to leak through a logged env dump, a child process inheriting the environment, or `/proc` than a value sitting in `os.environ`; exhaust's own virtual key to the proxy should take the same shape. This gives exhaust two things for the cost of one small service: a credential that can't leak through whatever the agent's own process does, and a budget ceiling enforced at the one point every model call must pass through, rather than hoping the agent's own accounting is honest.

Implemented as `exhaust.harness.credential_proxy`: a stdlib-only local HTTP server, no new dependency, since fronting one Anthropic-shaped endpoint doesn't need one. `load_api_key_from_file` refuses a credential file that's readable or writable by group or others, not just one that's missing; `write_virtual_key_file` writes the agent's own virtual key with the same `0600` restriction, closing the loop the ADR's own last sentence named. The budget check runs before a call is forwarded and real spend is recorded from the upstream response's actual `usage` once it returns, both against a rate the operator supplies (`TokenPricing`), not a hardcoded table this module would have to keep current as provider prices change. One real limit, not papered over: a single very large in-flight call can still push spend past the cap, since nothing aborts a call already forwarded mid-flight — the next call is what the cap actually stops. For Pi specifically, the virtual key reaches the subprocess exactly the file way this ADR asks for: `pi_adapter.provider_config` writes an `auth.json` whose `key` is Pi's own documented `!<command>` form (`!cat <virtual-key-file>`), confirmed from the real installed package's docs, never an environment variable. `exhaust run --anthropic-key-file` wires the whole path together and was verified against a real model call through a live Anthropic-compatible endpoint: the virtual key was all the proxy ever received from the caller, the real key only ever left this process toward the upstream, and the response's real token usage was priced and recorded correctly.
