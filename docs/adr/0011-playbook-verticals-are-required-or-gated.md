# The Playbook has no separate "module" concept — every vertical just carries a `required`/`gate` field

A Vertical is the only unit; there is no second kind of thing called a module, companion, or appendix. Every vertical in a Workspace's Playbook declares `required: true` (it runs on every Workspace regardless of what the Target turns out to be, for genuinely target-neutral concerns like injection, access control, business logic, or race conditions) or `required: false` with a `gate`: a recon-confirmed signal describing the trust boundary that has to actually be observed before this vertical turns on, never a language or dependency-name guess. Which non-required verticals exist and how broad they are is a separate, still-open decision; this ADR settles the shape, not the catalog.

Cloudflare's security-audit-skill is built on exactly this split, even though it names the two kinds of thing separately (nine always-on generic attack classes, plus ten domain "companion" files gated on an observed trust boundary): its explicit rule against selecting a module just because a keyword appears ("do not select a companion file merely because the language or dependency name appears") is precisely the discipline a `gate` field has to encode. We chose not to carry their two-noun split into exhaust's own vocabulary, since a vertical's `required`/`gate` fields say the same thing as plain data rather than requiring a second term the glossary has to define and keep consistent with the first. The reasoning for splitting at all is still theirs: a Target that is, say, a plain CLI tool shouldn't have to carry a client-side-browser vertical's irrelevant weight, and the gating decision is cheap to make once (at recon) rather than repeatedly guessed at by whichever agent happens to pick up a vertical next. It also keeps the required set honest: a vertical that has to justify its place on every single Workspace, with no target type to hide behind, had better be genuinely universal.

The industry-standard vulnerability-scanner template catalog reinforces the gating condition from a different angle, at industry scale: its own workflow files chain a cheap, narrow fingerprinting check first, and only fan out to a product's full, larger template set once that check actually confirms the product is present, never on a keyword or dependency-name guess. Nothing here changes exhaust's own decision; it is independent confirmation, from a tool run against millions of real targets, that gating on an observed, confirmed signal rather than an assumed one is the correct shape, not merely the cautious one.
