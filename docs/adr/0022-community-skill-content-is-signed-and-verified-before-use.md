# Community-contributed skill or template content is signed, and the signature is checked before use

Whenever exhaust accepts a skill, check definition, or template from outside its own pinned Rig catalog (community-contributed content, not from-scratch tools), each entry carries a cryptographic signature from its publisher, and the Harness verifies that signature before it ever runs the entry's content against a real Target. An entry whose signature is missing, unverifiable, or doesn't match is treated as untrusted and flagged, never silently executed.

The industry-standard vulnerability-scanner template catalog (13,000-plus stars, the de facto source of community-curated CVE and misconfiguration checks for its scanning engine) does exactly this: every official template file ends with a cryptographic digest line, generated at publish time and checked by the scanning engine before the template's logic runs. A community-contributed template without a valid signature is run with a visible warning rather than silently treated as equivalent to a vetted one. This matters for exhaust specifically because a skill or template is executable instruction content, not inert data: a tampered or maliciously submitted one is a direct path to getting the agent to take an action the user never reviewed, on the agent's own authority rather than the operator's. Pinning covers tool binaries (ADR 0012); this covers the separate case of pluggable, potentially community-sourced content that isn't a binary at all, and needs its own integrity check for the same reason.
