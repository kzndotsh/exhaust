# The Brief is its own file, referenced explicitly

The Brief lives in its own `BRIEF.md`, not folded into the Workspace's `AGENTS.md`. The Workspace's `AGENTS.md` (or `CLAUDE.md`, whichever the harness in use reads) carries an explicit reference to it, so it reaches the agent on purpose.

We first proposed delivering the Brief as the Workspace's `AGENTS.md` directly, on the premise that agent harnesses load it automatically. Checking that premise turned up two problems. Claude Code's own support for `AGENTS.md` is a fallback: if a `CLAUDE.md` exists anywhere in that directory or a parent, `AGENTS.md` is silently ignored, with no error, which would make the Brief vanish exactly when a Workspace happens to have both files. Codex truncates `AGENTS.md` past 32KB with no warning, which a real trust-model brief could exceed. Riding on a bare filename convention that behaves differently, undocumented, across harnesses is unacceptable for a document the agent's safety assumptions depend on. A dedicated file plus an explicit one-line reference in whichever config file the harness actually reads keeps the delivery mechanism visible and correct, and separates domain content (the Brief) from process instructions (`AGENTS.md`/`CLAUDE.md`).
