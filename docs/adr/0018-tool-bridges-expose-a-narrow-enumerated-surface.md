# Tool bridges expose a narrow, enumerated method surface, never a raw command passthrough

Each tool the Rig wraps gets a closed, named list of methods the bridge itself enforces, with a default branch that refuses anything not on the list. Whether a given call may mutate anything is checked by the bridge process itself, not merely advertised to the agent and trusted. No bridge accepts an arbitrary command string from the agent and hands it unfiltered to the underlying tool.

A reverse-engineering toolkit audited for this research shows both the right shape and the wrong one side by side, wrapping the same class of tool. Its Ghidra bridge is a closed switch over about thirty named methods with a hard default-throw, and a mutating call is rejected by the bridge itself when the session shouldn't allow one, not left to the agent's judgment. Its Cutter bridge, by contrast, accepts an arbitrary command string from an authenticated caller and passes it straight through, with only a loopback bind and a token check standing between the agent and the tool's full command surface. A narrow, bridge-enforced method list is a small amount of extra work per tool and it's the only one of the two that actually bounds what a mistaken or manipulated agent call can do; the alternative is a thin authentication layer wrapped around what is functionally an unrestricted shell into the tool.
