# The spine is a small always-on core plus recon-gated domain modules

The spine is not one flat list of verticals every Workspace walks identically. A small set of target-neutral classes (injection, access control, business logic, and similarly generic concerns) runs on every Workspace regardless of what the Target turns out to be. Beyond that core, domain-specific modules are selected in only when recon finds the trust boundary that module exists to cover, never by matching a language or dependency name. This ADR settles the spine's shape; which domain modules exist and how broad they are is a separate, still-open decision.

Cloudflare's security-audit-skill is built this way: nine always-on generic attack classes, plus ten domain companion files gated on an observed trust boundary, with an explicit rule against selecting a module just because a keyword appears ("do not select a companion file merely because the language or dependency name appears"). This is a strictly better shape than a flat list for two reasons. A Target that is, say, a plain CLI tool shouldn't have to carry a client-side-browser module's irrelevant weight, and the gating decision is cheap to make once (at recon) rather than repeatedly guessed at by whichever agent happens to pick up a vertical next. It also keeps the always-on core honest: a class that has to justify its place on every single Workspace, with no target type to hide behind, had better be genuinely universal.
