# A consequential real-Target action waits for a human; in-scope isn't enough

A `RealTargetCall` whose method the Rig bridge itself marks consequential does not dispatch the moment the Scope Contract confirms the target is authorized. It is held as a pending approval, keyed by a hash of the action's own fields (vertical, tool, method, params, target), until a human approves that exact action. Approving does not execute it; the agent must propose the same action again, and only then does the Harness dispatch it, so the Harness remains the only thing that ever calls the Rig. `SelfReport`'s exhaustion attestation is held the same way, under the same mechanism with a different trigger, since both are a case of a consequential claim that must not be taken on an agent's word alone. Whether a method is consequential is declared where that judgment already lives, at the bridge's own narrow method registration (ADR 0018), not by a separate risk classifier bolted on afterward.

This is deliberately a new, independent mechanism, not an extension of the per-vertical ledger's `blocked` state (ADR 0005, ADR 0015). The Scope Contract answers one question, is this target authorized at all, and a vertical's `blocked` state answers a second, coarser one, is this whole line of investigation stuck. Neither answers the question this ADR is about: should this one specific action, with these exact parameters, happen right now. Collapsing it into `blocked` would force every consequential action through the same heavy, whole-vertical pause that's meant for a stuck investigation, which is precisely the approval-fatigue failure mode this is meant to avoid, treating every gate as equally weighty teaches whoever's resolving them to stop looking closely at any of them. A pending approval is scoped to one action and resolves without touching the vertical's own state at all.

A companion research pass auditing harness-engineering principles and agent-security literature converged on this gap from four independent directions without anyone arguing for it directly: a Scope Contract gates a category, not an instance; a self-reported completion claim is a materially different, less verifiable assertion than a self-reported dead end, and deserves its own check rather than inheriting `blocked`'s; and Anthropic's own shipped `/goal` feature already ships the underlying pattern this borrows, a structurally separate check rather than trusting the party making the claim. None of those sources were about exhaust, which is what makes the convergence worth acting on rather than treating as one opinion among several.

There is deliberately no bypass flag for this gate, not even for unattended runs. A coding agent's own `--dangerously-skip-permissions`-style escape hatch is defensible because it's scoped to a sandbox the operator already controls; this gate exists specifically for the one category, a real-Target action, where that isn't true. A flag that skips it would also become the exact attack surface the gate is meant to close, a predictable switch a tired operator or a manipulated one flips once, after which the gate is gone for the action that actually needed it. Unattended operation is still possible without one: a human pre-approves a specific action, or a specific tool-and-method pairing for a vertical, through the same mechanism, before the run starts, so dispatch still only ever happens because a human looked at that exact thing at some point, not because a config value turned the check off.
